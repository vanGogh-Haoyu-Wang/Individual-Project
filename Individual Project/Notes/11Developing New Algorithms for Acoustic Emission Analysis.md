In this project, new algorithms should not mean inventing an entirely new mathematical theory from scratch. A more realistic and valuable interpretation is to develop reproducible, material-aware AE analysis modules in Python and Julia. This would move the work beyond MATLAB translation and toward validated scientific workflows: data preparation, event detection, signal cleaning, feature extraction, clustering, damage-stage interpretation, and comparison against physical evidence. The novelty would lie in making the AE pipeline transparent, testable, open-source, and adaptable to different materials.

For steel structures, the strongest direction is an algorithmic pipeline for corrosion, cracking, fatigue, and stress-corrosion damage. This could include adaptive noise filtering, robust AE event detection, extraction of time-domain and frequency-domain features, and clustering methods that do not assume simple spherical groups. Instead of relying only on k-means, methods such as DBSCAN, Gaussian mixture models, OPTICS, or SOM could be compared. A further algorithm could track damage progression over time by linking AE event rate, cumulative energy, frequency shifts, and load or inspection history.

For composite materials, the readings suggest a transferable but different algorithmic focus. Moving-RMS methods can identify important damage windows while preserving access to raw waveforms. Multi-peak FFT analysis can detect weaker simultaneous damage modes hidden by the dominant peak frequency. Wavelet or empirical-wavelet methods can estimate band-energy contributions associated with matrix cracking, delamination, debonding, fibre fracture, and fibre pull-out. A useful new algorithm would therefore be a multi-variant damage index combining RMS intensity, FFT peak hierarchy, wavelet band energy, and event timing.

A necessary addition is a data-input and preprocessing algorithm. The inspected workbook, `Commercial Tensile Tests.xlsx`, has `CT07` and `CT09` sheets with 15 columns, but each sheet combines different data domains. Columns `A:D` contain mechanical data, while `E:N` contain AE-derived data; they start on different rows and have different valid lengths. `CT07` has 1,807 valid mechanical pairs and 5,850 AE pairs; `CT09` has 1,730 mechanical pairs and 9,733 AE pairs. The first rows mix labels, units, constants, and formulas, and some columns are helper outputs such as cumulative RMS, normalised RMS, normalised AE energy, and max-value cells. This is not a clean rectangular table, so a global `dropna` or `dropmissing` step could delete valid AE events and invalidate later clustering.

Therefore, CSV should be proposed as a validated intermediate research format, not necessarily as the only archive format. The Excel workbook could be split into `specimens.csv`, `mechanical.csv`, `ae_events.csv`, and `preprocessing_log.csv` or `metadata.json`. The preprocessing algorithm should inspect sheet names and used ranges, detect physical column positions, separate mechanical and AE domains, coerce each signal independently to numeric, preserve pairwise finite masks, recompute or verify formula-derived columns, and export CSV files with a schema and checksum report.

Python and Julia should be used as complementary tools. Python is the practical first layer for Excel-to-CSV conversion, schema inspection, validation, orchestration, and plotting, using `pandas/openpyxl`, `NumPy/SciPy/scikit-learn`, and Matplotlib. The comparison experiments showed that Python handled physical spreadsheet columns and shared-X twin-axis plotting more reliably. Julia remains valuable for performance-sensitive numerical kernels, repeated FFT or wavelet operations, clustering experiments, and reproducible scientific scripts, ideally consuming the validated CSV or Arrow/Parquet-style intermediate data. If Julia reads Excel directly, raw `XLSX.jl` worksheet access is safer than automatic `XLSX.readtable` when physical column positions matter. In both languages, tests should check row counts, selected numeric values, event timing, plot structure, dependency versions, and MATLAB reference arrays where available.
