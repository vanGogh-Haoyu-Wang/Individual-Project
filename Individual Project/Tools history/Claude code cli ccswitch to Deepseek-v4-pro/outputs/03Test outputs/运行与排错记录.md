## 遇到的问题与解决过程

### 1. Juliaup 在受限环境中无法创建锁文件

第一次执行 `julia --version` 时，Juliaup 报错：

```text
Could not create lockfile `/Users/vangogh/.julia/juliaup/.juliaup-lock`:
Operation not permitted (os error 1)
```

原因是 Juliaup 启动器会写入用户目录下的锁文件，而受限运行环境不允许该写入。允许访问用户级 Julia 配置后，Juliaup 启动器仍长时间没有返回，因此终止了该启动器进程。

解决办法：绕过 Juliaup 启动器，直接调用已安装的 Julia 1.12.6 二进制文件：

```text
/Users/vangogh/.julia/juliaup/julia-1.12.6+0.aarch64.apple.darwin14/Julia-1.12.app/Contents/Resources/julia/bin/julia
```

直接执行返回 `julia version 1.12.6`。

### 2. 脚本依赖未加入当前 Julia 环境

直接加载脚本所需包时，首先报错：

```text
ArgumentError: Package XLSX not found in current path.
```

脚本依赖 `XLSX`、`DataFrames`、`Plots`。为避免改动用户的全局 Julia 项目，创建了临时项目 `/tmp/codex_tensile_env` 并加入这三个包。

安装时出现一次 `Could not resolve host: pkg.julialang.org` 警告；本机已有可用的注册表/包缓存，因此版本解析、项目写入和预编译仍正常完成。最终使用版本为：

- `XLSX` 0.11.10
- `DataFrames` 1.8.2
- `Plots` 1.41.6
- `GR` 0.73.26

### 3. 辅助 Excel 检查工具存在 macOS 原生模块签名冲突

最初尝试用工作区自带的表格检查工具只读查看 Excel 时，`skia-canvas` 原生模块因 Team ID 不一致而被 macOS 拒绝加载。该问题与 Excel 文件及 Julia 脚本无关。

解决办法：停止使用该辅助工具，改用脚本本身依赖的 `XLSX.jl` 只读检查工作簿，避免改动原始工作簿。

### 4. 工作表名称与脚本默认值不一致

脚本默认工作表名称是 `CT-07`；实际工作簿包含：

```text
CT07
CT09
```

解决办法：运行时选用 `CT07`。这与脚本的默认试样意图及 5 张图中 4 张的 T07 标题一致。

### 5. 脚本的数据读取假设与实际工作簿表头布局不一致

即使把表名改为 `CT07`，原 `main` 仍稳定报错：

```text
BoundsError: attempt to access data frame with 9 columns at index
[1, 3, 4, 5, 9, 10, 12, 14]
```

堆栈定位到脚本第 44 行：

```julia
df_clean = dropmissing(df[:, key_cols])
```

根因：`CT07` 第一行的 A–D 单元格为空，拉伸数据的名称和单位位于第 2、3 行；AE 数据的标题则从第一行 E 列开始。`XLSX.readtable` 使用第一行作为表头，因此忽略了 A–D 空标题列，只生成 9 列 DataFrame，而脚本继续访问第 10、12、14 列。

原始单元格检查表明数据并未损坏：

- 拉伸时间/应变/应力：1,807 点；
- AE 时间、RMS、累计 RMS、能量及累计能量：各 5,850 点；
- RMS、累计 RMS、AE 能量、累计 AE 能量的归一化范围均为 0–1。

解决办法：不修改脚本文件，加载脚本后直接复用其中的 5 个绘图函数，并按实际原始单元格范围读取数值：

| 变量 | CT07 范围 | 点数 |
|---|---:|---:|
| `t1` | `A4:A6000` 中的数值 | 1,807 |
| `strain` | `C4:C6000` 中的数值 | 1,807 |
| `stress` | `D4:D6000` 中的数值 | 1,807 |
| `time` | `E2:E6000` 中的数值 | 5,850 |
| `rms` | `I2:I6000` 中的数值 | 5,850 |
| `cumrms` | `J2:J6000` 中的数值 | 5,850 |
| `energy` | `L2:L6000` 中的数值 | 5,850 |
| `cumenergy` | `N2:N6000` 中的数值 | 5,850 |

每个范围只保留数值单元格，因此自动排除了多行表头、单位和尾部空白。

### 6. 原脚本只显示图，不会实际保存文件

脚本中的 5 个 `savefig` 调用位于注释块中；直接运行只会调用 `display`，无法得到要求的 5 个图片文件。在无图形界面的批处理环境中，还需要避免 GR 尝试启动交互窗口。

解决办法：设置 `GKSwstype=100` 使用无界面 GR 输出；调用原脚本的 `fig1_...` 至 `fig5_...` 函数后，显式执行 5 次 `savefig`，保存到本输出目录。
