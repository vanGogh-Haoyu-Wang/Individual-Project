# 阅读笔记：Translating code with Large Language Models and human-in-the-loop feedback

**文献标题:** Translating code with Large Language Models and human-in-the-loop feedback **作者:** Gabriele Dario De Siano 等人 (2025) **发表期刊:** Information and Software Technology **研究主题:** 探讨在利用 [[Large Language Models (LLMs)]] 进行代码翻译时，如何通过引入 [[Human-in-the-loop]] (人在回路) 反馈机制来提升代码转换的精确度、可靠性与工作效率。

## 核心观点与发现 (Key Findings)

- **接受非完美输出 (Imperfect Outputs)：** LLM 虽然能极大地降低代码迁移（如将庞大陈旧的逻辑转为现代语言）时的认知负荷，但模型直接生成的初始代码往往无法无缝运行。研究实验证实，带有少量瑕疵的初始代码模型，依然能显著提升软件工程师在翻译任务中的整体效率。

- **[[Human-in-the-loop]] (HITL) 的核心价值：** 相比于期待大模型“一次性输出完美代码”，将人类专家深度整合进翻译流程中是更加务实的策略。人类工程师通过审查 AI 输出，识别深层逻辑错误并给予反馈，这种协作范式能最大化减少错误率。

- **[[Iterative Refinement]] (迭代微调)：** 精准的提示词设计（Prompt Design）与迭代机制密不可分。在处理代码迁移任务（如 SQL 方言转换）时，通过人工审核与多轮反馈交替进行的迭代微调，能让最终代码达到极高的功能等价性。

- **工程角色的重塑：** 在自动化代码迁移项目中，开发者的角色从传统的“代码编写者”转变为“审查者与调度员（Reviewer & Evaluator）”。对于 LLM 生成的代码，必须执行与审查人类同事代码同等严格的测试协议。

## 对毕设项目的启发 (Inspirations for the MSc Project)

1. **构建“人在回路”的本地工作流：** 充分发挥本地大语言模型（如通过 Ollama 或 LM Studio 部署的 Qwen 等系列模型）低延迟和数据隐私性高的优势，将本地 AI 终端与 VSCodium 深度结合。在将声发射分析的 MATLAB 算法转换为 Python 的过程中，主动切入“人在回路”的核心环节。不要盲目依赖一键全自动转译，而是针对每一个特定的功能函数，先让模型生成 Python 初稿，随后利用在材料科学信号处理和 Python 编程方面的专业知识，人工核对核心算法的逻辑准确性。

2. **记录并结构化 [[Feedback]] (反馈指令)：** 将审查出的代码逻辑错误转化为清晰、精确的反馈 Prompt，再次输入给模型进行修复。可以在 Obsidian 知识库中建立一个专门的“人机协作追踪看板”，详细记录针对哪些具体的 MATLAB 语法特性（如矩阵索引、特定工具箱函数），我是如何通过特定的提示词引导模型完成修复的。这种对“迭代反馈过程”的完整留存，正是毕设项目 P15 要求中“评估 AI 引入的错误及 LLM 调试应用”的最核心产出。

3. **静态编译器与 LLM 的人机协同：** 针对刚刚搭建好的静态翻译工具 SMOP，可以设计一套混合架构工作流。先利用 SMOP 生成基础的 Python 骨架，当遭遇 SMOP 难以处理的复杂 MATLAB 动态特性时，人工提取出具体断点和报错上下文交由 LLM 处理，最后再由人工将修正后的代码片段合并（Merge）。这种结合了“确定性工具+概率性模型+专家审核”的模式，能够最大化保障底层算法逻辑的严谨性。

# English Translation

**Paper Title:** Translating code with Large Language Models and human-in-the-loop feedback
**Authors:** Gabriele Dario De Siano et al. (2025)
**Journal:** Information and Software Technology
**Research Topic:** Exploring how to improve the accuracy, reliability, and efficiency of code conversion by introducing [[Human-in-the-loop]] (HITL) feedback mechanisms when using [[Large Language Models (LLMs)]] for code translation.

## Key Findings

- **Acceptance of Imperfect Outputs:** Although LLMs can greatly reduce the cognitive load during code migration (such as converting massive legacy logic into modern languages), the initial code directly generated by the models often cannot run seamlessly. Research experiments have confirmed that even with a small number of flaws, initial code models can significantly improve the overall efficiency of software engineers in translation tasks.

- **The core value of [[Human-in-the-loop]] (HITL):** Rather than expecting LLMs to "output perfect code in one go," deeply integrating human experts into the translation process is a more pragmatic strategy. Human engineers minimize error rates by reviewing AI outputs, identifying deep logical errors, and providing feedback.

- **[[Iterative Refinement]]:** Precise Prompt Design is inextricably linked to iterative mechanisms. When handling code migration tasks (such as SQL dialect conversion), iterative refinement—alternating between manual review and multiple rounds of feedback—can lead to extremely high functional equivalence in the final code.

- **Reshaping the Engineering Role:** In automated code migration projects, the developer's role shifts from the traditional "code writer" to a "Reviewer & Evaluator." For code generated by LLMs, testing protocols as rigorous as those used for reviewing human colleagues' code must be executed.

## Inspirations for the MSc Project

1. **Build a "Human-in-the-Loop" Local Workflow:** Leverage the advantages of low latency and high data privacy offered by local large language models (such as the Qwen series deployed via Ollama or LM Studio), and deeply integrate the local AI terminal with VSCodium. In the process of converting MATLAB algorithms for acoustic emission analysis to Python, actively cut into the core link of "human-in-the-loop." Do not blindly rely on one-click fully automated transpilation; instead, for each specific functional function, let the model generate an initial Python draft first, then use your professional knowledge in materials science signal processing and Python programming to manually verify the logical accuracy of the core algorithm.

2. **Record and Structure [[Feedback]] Instructions:** Transform the identified logical errors in the code into clear and precise feedback prompts, and input them back into the model for repair. A dedicated "Human-Machine Collaboration Tracking Board" can be established in the Obsidian knowledge base to record in detail which specific MATLAB syntax features (such as matrix indexing or specific toolbox functions) were addressed and how the model was guided through specific prompts to complete the repair. This complete preservation of the "iterative feedback process" is precisely the core output for "evaluating AI-introduced errors and LLM debugging applications" required by the MSc project P15.

3. **Human-Machine Synergy between Static Compilers and LLMs:** Design a hybrid architecture workflow for the recently established static translation tool SMOP. Use SMOP to generate a basic Python skeleton first. When encountering complex MATLAB dynamic features that SMOP struggles to handle, manually extract the specific breakpoints and error contexts to be handled by the LLM, and finally have a human merge the corrected code snippets. This model, which combines "deterministic tools + probabilistic models + expert review," can maximize the assurance of the rigor of the underlying algorithmic logic.
