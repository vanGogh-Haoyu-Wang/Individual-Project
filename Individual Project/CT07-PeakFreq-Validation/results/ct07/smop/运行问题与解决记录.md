# SMOP 0.41 CT07 双路径调试、运行与数值验证记录

## 1. 结论摘要

SMOP 0.41 能识别 `CT07.m` 的语句顺序、Excel 文件与 sheet、MATLAB
物理列号、五图结构、轴范围、标题和颜色，但原始译出文件不能执行。
首个真实错误不是数据问题，而是 SMOP 在模块顶层生成了四空格缩进，
导致 `IndentationError`。

冻结原始输出后完成了两条独立恢复路径：

1. **Script-fixed**：将不可用的 SMOP runtime 调用替换为
   pandas/NumPy/matplotlib，同时保留译出的计算和绘图顺序。
2. **Runtime-compatible**：只去除非法顶层缩进，原有 SMOP 语句保持
   不变，由 CT07-scoped `libsmop.py` 提供 Excel、1-based indexing 和
   `yyaxis`/绘图兼容。

两条路径均得到 1,807 条 mechanical、5,850 条 AE，分别与 MATLAB
R2026a oracle 完成逐行数值闭环，并各生成五张有效 PNG。

## 3. Translation smoke test

最小输入：

```matlab
a = 1;
b = 2;
c = a + b;
```

`smop` 退出码为 0 并生成 Python 文件，但 `py_compile` 稳定失败：

```text
IndentationError: unexpected indent (smoke.py, line 5)
```

这个反馈环证明“SMOP 命令成功”只表示输出了文本，不表示生成的 Python
可编译或可运行。

## 5. Ranked failure hypotheses 和逐项证据

首次失败后，按从最接近执行入口到最深 runtime 的顺序验证：

1. **Generator syntax**：raw script 第 5 行顶层缩进导致
   `IndentationError`。已实证。
2. **Runtime packaging**：只去掉顶层缩进后出现
   `ModuleNotFoundError: libsmop`。已实证。
3. **Python 2 runtime assumption**：显式暴露 SMOP package 中的
   `libsmop.py` 后出现 `ModuleNotFoundError: __builtin__`。已实证。
4. **旧 NumPy API**：临时 alias `__builtin__` 后出现
   `np.NaN was removed in NumPy 2.0`。已实证。
5. **缺失 CT07 I/O/runtime surface**：临时补足上述两个 import 后，
   下一错误为 `NameError: xlsread`。已实证。

静态检查还确认 SMOP runtime 没有 `figure`、`plot`、`scatter`、
`yyaxis`、标签、轴范围、标题和 grid 实现，原始 `concat` 还包含
`pdb.set_trace()`。

因此，本实验不把这些问题误记为 workbook 或 CT07 算法错误。

## 6. Syntax-normalized probe

Runtime 路径需要一个可编译入口，因此增加确定性 normalizer：

```text
raw/normalize_smop_top_level.py
raw/CT07_smop_syntax_normalized.py
SHA-256: 0d1c4be906477d9750f26455d8812fdd843d4b2f8ddd47fb92aeb905a20c814b
```

该步骤只删除 SMOP 自动加入的一个四空格顶层前缀，不修改函数名、变量、
常量、列号、计算或绘图语句。它不能被称为原始输出成功运行。

## 7. Script-fixed 路径

`script-fixed/CT07_smop_fixed.py` 暴露：

```python
run_ct07(input_path, sheet_name, output_dir)
```

主要修复：

- 使用 pandas 替代不存在的 `xlsread`；
- mixed cells 安全转换为 numeric/NaN；
- mechanical 和 AE 使用两套独立 complete-case mask；
- 保留 SMOP 译出的列号与五图顺序；
- 使用 matplotlib `twinx()` 实现双 Y 轴；
- 增加 headless CSV、PNG 和 metadata 输出。

没有使用统一 `dropna`，因此保留了 matrix row 2、3 的前两条 AE 记录。

## 8. Runtime-compatible 路径

`runtime-compatible/libsmop.py` 只实现本 CT07 raw script 使用的表面：

- `xlsread`；
- `matlabarray` 和 `data(arange(), column)` 的 1-based indexing；
- `concat`、有限值 `max`、`copy(figure)`；
- `plot`、`scatter`、labels、limits、title、grid；
- 通过 matplotlib `twinx()` 实现 `yyaxis left/right`。

`runtime-compatible/run_smop_ct07.py` 执行 syntax-normalized SMOP script，
捕获其八个数据变量和五个 figure，再独立建立 mechanical/AE masks 和
输出合同。

该模块是 **CT07-scoped runtime adapter**，不是完整或通用的 libsmop
现代化实现。

## 10. 测试和负向验证

`test_smop_ct07.py` 共 4 tests，覆盖：

- raw hash 和稳定 `IndentationError`；
- syntax-normalized script 可编译但无 runtime 时稳定失败；
- 1-based column、`arange()`、`concat` 和共享 X 轴；
- 两条真实运行路径与 MATLAB oracle；
- 1,807/5,850 和十张 PNG；
- 删除、增加、重排、错位记录时 comparator 必须失败。

最终结果：

```text
4 passed
```

## 11. 保守结论和限制

> SMOP 0.41 generated a structurally recognisable Python translation of
> CT07.m, but the unmodified output was not executable because the supplied
> runtime did not support the required Excel and plotting workflow and
> retained obsolete Python assumptions. Two audited recovery paths were
> evaluated: direct repair of the generated script and a CT07-scoped
> compatibility runtime. Both repaired paths were numerically validated
> against the MATLAB CT07 reference. This is evidence for recoverability with
> human intervention, not evidence that SMOP provides an automatic end-to-end
> CT07 migration.

本轮没有处理 Peak_Freq、通用 MATLAB runtime、完整 libsmop 现代化、GUI、
性能排名或像素级图片比较。SMOP 仍是独立 transpiler baseline，不加入
8 个 LLM candidate 的计数或排名。
