# 数据处理架构迁移技术总结：从 MATLAB+XLSX 走向 Python/Julia+Parquet

## 1. 核心格式对比：Parquet vs CSV

### 1.1 为什么 Parquet 是现代数据分析的首选？
*   **列式存储 (Column-oriented)**：与 CSV 的行式存储不同，Parquet 将同一列的数据物理存放在一起。
    *   **列裁剪 (Column Pruning)**：如果一个表有 100 列，但你的脚本（如 `CT07.m`）只选择其中 8 列，Parquet 允许程序只从磁盘读取这 8 列的字节块，减少 90% 以上的 I/O 开销。
    *   **极高压缩率**：由于同一列数据类型相同且往往有规律（如随时间递增的采样值），Parquet 能利用 Snappy 或 Zstd 算法实现极高压缩，体积通常仅为 CSV 的 10%-20%。
*   **强类型 Schema**：文件自带列名和数据类型定义，彻底解决 CSV 常见的数字被误读为字符串、日期格式混乱等问题。

### 1.2 优缺点权衡
| 特性 | CSV | Parquet |
| :--- | :--- | :--- |
| **可读性** | 纯文本，记事本可开 | 二进制，需工具读取 |
| **I/O 性能** | 随数据量线性增长（全扫） | 极高性能（按需读取列） |
| **写入成本** | 低 | 较高（需在内存缓冲和压缩） |
| **最佳场景** | 配置文件、小规模数据预览 | 大规模实验数据、声发射(AE)采样 |

## 2. 工具链对比：Python (Polars) vs Julia

在处理 500MB 级别及以下的实验采样数据时，两者的表现各有千秋：

### 2.1 Python + Polars (新一代性能霸主)
*   **底层引擎**：基于 Rust 编写，完全利用多核并行计算。
*   **核心优势**：
    *   **Lazy API**：Polars 不会立刻执行你的代码，而是先优化“查询计划”。如果它发现你最后只要 8 列，它会在读取阶段就智能地只加载这 8 列。
    *   **内存安全**：基于 Apache Arrow 内存标准，极少产生数据副本，内存占用远低于 Pandas。
*   **绘图体验**：即时启动，Matplotlib 或 Plotly 生态极其成熟。

### 2.2 Julia (科学计算的“黑科技”)
*   **CSV 读取**：`CSV.jl` 是目前公认的最快 CSV 解析器，其多线程解析文本的能力在处理原始文本流文件时无人能及。
*   **原生性能**：Julia 的计算速度接近 C/C++，对于声发射信号处理（如 FFT、小波变换）具有天然优势。
*   **不足**：**首次绘图延迟 (TTFP)**。第一次运行绘图库时需要即时编译（JIT），会有几秒钟的等待，适合批量处理。

### 2.3 性能拐点逻辑
*   **Python (Polars) + Parquet**：在列裁剪场景下效率最高，是目前工业界的顶级组合。
*   **Julia + CSV**：在必须解析大量原始文本行的场景下，Julia 的多线程优势最明显。

## 3. 关于“行多列少”的数据结构误区

针对拉伸实验数据（百万行级别，但仅十几个传感器参数）：
*   **结论**：**千万不要把行转成列！**
*   **原理**：Parquet 最擅长处理“窄长型”数据。你感觉“行比列多太多”正是列式存储发挥威力的最佳形状。
*   **误解澄清**：所谓“列式”，是指**硬盘上的排列方式**。Parquet 会把这 100 万行的“应力”数据打包成一个连续块，读取时就像从传送带上直接切下一段，比 CSV 在几百万个逗号中搜索快得多。

## 4. 实战建议：转换与迁移

### 4.1 如何转换 XLSX 文件？
Excel (.xlsx) 本质上是压缩的 XML，读取极慢。建议一键转为 Parquet：

**Python 批量转换方案：**
```python
import pandas as pd
excel_file = "Tensile-processed.xlsx"
sheet_names = pd.ExcelFile(excel_file).sheet_names

for sheet in sheet_names:
    df = pd.read_excel(excel_file, sheet_name=sheet)
    df.to_parquet(f"{sheet}.parquet", index=False)
```

### 4.2 针对 `CT07.m` 的 CSV 样本分析
*   **发现问题**：你的原始 CSV 存在多行表头、列名偏移（前面有空列）的情况。
*   **MATLAB 的弊端**：使用 `data(:, 4)` 这种数字索引极其脆弱，一旦 Excel 结构变动就会报错。
*   **优化方案**：在转为 Parquet 时清理表头，以后在 Polars 或 Julia 中通过列名（如 `pl.col("Stress")`）调用，既保证了速度，又增强了代码的健壮性。

## 5. 总结建议
1.  **彻底告别 XLSX**：将其作为原始存档，计算过程一律使用 **Parquet**。
2.  **首选方案**：**Python + Polars + Parquet**。这是目前开发效率、绘图速度和计算性能平衡得最好的方案。
3.  **科学进阶**：如果你后续涉及极其复杂的物理公式运算或自定义信号处理算法，尝试 **Julia + Parquet2.jl**。
